## Manip 01 — Le REPL et la LED

Tout se fait dans le **Shell de Thonny** (la console en bas). On tape une instruction, l'ESP32 l'exécute et affiche le résultat.

### Découverte : calculs et variables

```python
>>> 2 + 3 * 4                     # la multiplication est prioritaire
14
>>> 15 / 3 - 1                    # la division retourne un "float"
4.0
>>> 13 // 4                       # division entière
3
>>> 13 % 4                        # modulo (reste de la division)
1
>>> 2 ** 8                        # puissance : 2 exposant 8
256
```

```python
>>> vitesse1 = 36
>>> vitesse2 = 42
>>> print("Moyenne :", (vitesse1 + vitesse2) / 2)
Moyenne : 39.0
>>> type(vitesse1)                 # int = nombre entier
<class 'int'>
>>> type("Bonjour")               # str = chaîne de caractères
<class 'str'>
```

### Contrôler la LED intégrée

La LED bleue sur la carte est connectée au **GPIO 2**. On la commande depuis le Shell :

```python
>>> from machine import Pin
>>> led = Pin(2, Pin.OUT)          # GPIO 2 en sortie
>>> led.value(1)                   # la LED s'allume !
>>> led.value(0)                   # la LED s'éteint
>>> led.on()                       # raccourci pour allumer
>>> led.off()                      # raccourci pour éteindre
>>> Pin(2, Pin.OUT).value(1)       # tout en une seule ligne
```

<div class="rounded-xl border border-base-200/60 bg-base-200/20 p-4 my-4">
  <p class="text-xs text-base-content/50">
    <strong>Ctrl+C</strong> : arrête le programme en cours ·
    <strong>Ctrl+D</strong> : redémarre l'ESP32 ·
    <strong>Flèche Haut</strong> : rappelle la dernière commande ·
    <code>Pin(n, Pin.OUT)</code> = broche en sortie ·
    <code>value(1)</code> = 3,3V → allumée ·
    <code>value(0)</code> = 0V → éteinte
  </p>
</div>

<Prediction question="Que renvoie `type(15 / 3)` — un `int` ou un `float` ?">

Un **`float`**. En Python, la division `/` renvoie toujours un nombre à virgule, même quand le résultat tombe juste : `15 / 3` donne `5.0`, pas `5`.

Pour obtenir un entier, il faut la division entière : `15 // 3` renvoie bien `5`.

</Prediction>

<ToiDeJouer>

- Combien de secondes dans une année ? Tape `365 * 24 * 3600`
- Compare les trois divisions : `10 / 3`, puis `10 // 3`, puis `10 % 3`
- Crée une variable : `prenom = "Vincent"` puis `print("Bonjour", prenom)`
- Fais clignoter la LED **à la main** : alterne `led.on()` et `led.off()` en rappelant les commandes avec la **flèche Haut**
- Quel type renvoie `type(3.14)` ?

</ToiDeJouer>

<Prediction question="Si tu remplaces les deux `time.sleep(0.5)` par `time.sleep(0.01)`, que verras-tu ?">

La LED **semblera allumée en permanence**, mais moins lumineuse qu'à pleine puissance.

À 50 clignotements par seconde, l'œil ne distingue plus les alternances : au-delà d'environ 25 Hz, la persistance rétinienne les fusionne. Comme la LED n'est allumée que la moitié du temps, on perçoit une luminosité moyenne.

C'est exactement le principe du **PWM** — la manipulation suivante.

</Prediction>

- Remplace `0.5` par `0.1` → clignotement rapide
- Remplace `0.5` par `2.0` → clignotement lent
- Mets des durées différentes : `0.1` allumé, `0.9` éteint — comme un phare
- Essaie la version compacte : `led.value(not led.value())` inverse l'état à chaque tour

</ToiDeJouer>

## Manip 03 — La LED qui "respire" (PWM)

Le **PWM** allume et éteint la LED des centaines de fois par seconde.
L'œil perçoit une luminosité intermédiaire. `duty` va de **0** (éteint) à **1023** (pleine puissance).

<GitHubCodeBlock
  repo="vincent-herm/fablab-esp32-ateliers"
  file="atelier0-initiation/manip03_led_pwm.py"
  language="python"
  title="manip03_led_pwm.py"
/>

<ToiDeJouer>

Après un `Ctrl+C`, règle la luminosité à la main dans le Shell :

- `led.duty(0)` éteinte · `led.duty(100)` très faible · `led.duty(512)` moitié · `led.duty(1023)` maximum
- Change `freq=1000` en `freq=1` → tu **vois** le clignotement qui se cachait derrière le PWM
- Change le pas : `range(0, 1023, 50)` au lieu de `5` → la montée devient saccadée
- Passe `sleep_ms(5)` à `sleep_ms(20)` → respiration plus lente

**À retenir :** le PWM ne sert pas qu'aux LED. C'est aussi lui qui règle la vitesse d'un moteur et la position d'un servomoteur.

</ToiDeJouer>

## Manip 04 — Lire le bouton BOOT

Le bouton BOOT (GPIO 0) est sur toutes les cartes ESP32.
Attention à la **logique inversée** : relâché = 1, appuyé = 0.

<GitHubCodeBlock
  repo="vincent-herm/fablab-esp32-ateliers"
  file="atelier0-initiation/manip04_bouton_boot.py"
  language="python"
  title="manip04_bouton_boot.py"
/>

<Prediction question="Pourquoi le bouton vaut-il `1` au repos et `0` quand on appuie ?">

À cause du **pull-up interne**, activé par `Pin.PULL_UP`.

Au repos, une petite résistance interne tire la broche vers 3,3 V → elle lit `1`. Appuyer sur le bouton relie la broche directement à la masse (GND) → elle lit `0`.

Sans ce pull-up, la broche serait « flottante » : elle capterait le bruit ambiant et renverrait des valeurs au hasard. On appelle ça une logique **active bas**, et elle est très courante en électronique.

</Prediction>

<ToiDeJouer>

- Enlève `Pin.PULL_UP` (garde `Pin(0, Pin.IN)`) → observe les valeurs devenir erratiques, puis remets-le
- Passe `sleep(0.2)` à `sleep(0.01)` → la console est inondée. Pourquoi 200 ms est-il un bon compromis ?
- Ajoute un compteur qui affiche le nombre total d'appuis

</ToiDeJouer>

## Manip 06 — Temporisateur d'éclairage

On appuie sur le bouton → la LED s'allume **2 secondes** puis s'éteint seule. Si on réappuie pendant que c'est allumé, le compteur repart — exactement comme une **minuterie d'escalier**.

Le principe : un **compteur** démarre à 20 à chaque appui. À chaque tour de boucle (0,1 s), le compteur descend de 1. La LED est allumée tant que le compteur est positif.
